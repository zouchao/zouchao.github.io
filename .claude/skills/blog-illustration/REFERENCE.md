# 博客配图视觉规范

所有文章配图（封面 + 插图）共用这一套设计语言。范本：
`assets/img/posts/ssh-config-notes/cover.svg`（先读它，照它的语法画）。

## 画布与产物

- 画布固定 `1600×900`，`viewBox="0 0 1600 900"`（封面和插图都用这个比例）。
- 源文件 `assets/img/posts/<slug>/xxx.svg`，PNG 用本 skill 的脚本渲染：
  `bash .claude/skills/blog-illustration/scripts/render-svg.sh assets/img/posts/<slug>/xxx.svg`
  （产出同目录同名 `.png`，2400×1350、128 色量化，体积应 ≤ 300KB）。
- `<slug>` = 文章文件名去掉日期前缀和 `.md`。

## 色板（只用这些）

| 用途 | 值 |
| --- | --- |
| 背景渐变 | `#0d1526 → #121d36`（对角 linearGradient） |
| 背景点阵 | `#8ea2c8` opacity `0.10`，40px 网格 r=1.5 |
| 卡片底 / 描边 | `#131d35` / `#27385e`（stroke-width 1.5，rx 14–16） |
| 主文字 / 次文字 / 弱文字 | `#f1f5f9` / `#94a3b8` / `#5d6f92` |
| 强调色（每张最多用 3 个） | teal `#34d399`、amber `#fbbf24`、blue `#60a5fa`、pink `#f472b6`、violet `#a78bfa` |
| 连接线 / 箭头 | `#4a5f92`，`stroke-dasharray="1 7"`，线帽 round，末端 arrow marker |
| 终端红绿灯 | `#ff5f57` `#febc2e` `#28c840` |

背景可加 1–2 个大半径 radialGradient 光晕（强调色，opacity ≤ 0.10）。

## 字体

- 等宽：`font-family="SF Mono, Menlo, Consolas, monospace"`（命令、文件名、配置、IP）
- 中文/说明：`font-family="PingFang SC, Hiragino Sans GB, sans-serif"`
- 字号阶梯：大标题 88 / 卡片标题 24 / 正文 17–20 / 注脚 14–16

## 版式语法（按需组合，不必全用）

1. **页眉**：左上大号等宽 motif（如 `~/.ssh`、`curl -v`、`go build`）+ 可选光标色块；
   光标 rect 的 x = 标题 text 的 x + 字符数 × 字号 × 0.60 + 14（间隙固定 14px），
   压字或离太远都算错；
   下一行中文副标题 27px `#94a3b8`，概括文章三件事。
2. **终端卡片**：标题栏（红绿灯 + 居中 16px 标题）+ 等宽正文行；重点行用
   `fill="#fbbf24" opacity="0.09"` 的圆角矩形垫底高亮；`$` 提示符用 teal。
3. **节点卡片**：标题 24px 粗 + 第二行 17px「主体 → 去向」，主体用强调色。
   左侧可放线性小图标（钥匙、锁、齿轮、数据库圆柱……用 path 画，**禁止 emoji**）。
4. **chip**：圆角矩形 + 居中 18px 等宽，描边用强调色 55% 不透明，装关键配置项/结论。
5. **连接**：卡片之间用虚线贝塞尔 + arrow marker 表达流向；一条线上可挂锁/钥匙图标。
6. **水印**（可选）：右上角 15px 等宽、opacity 0.45，放文章里真实存在的指纹/哈希/报错串。

## 文字排布硬规则（防溢出）

- SVG 是 XML：文本里的 `&` 必须写 `&amp;`（shell 的 `&&` 就是 `&amp;&amp;`），
  `<`、`>` 同理用 `&lt;` `&gt;`。否则 Chrome 渲染到第一个错误就截断。

- 四周留白 ≥ 80px；卡片内左右 padding ≥ 32px。
- 估宽公式：等宽字符 ≈ 字号 × 0.60；CJK 字符 ≈ 字号 × 1.0；混排分段相加。
  例：680 宽卡片（内宽 616）放 19px 等宽 → 单行 ≤ 54 字符。
- 终端卡片正文 ≤ 9 行；文章内容多就挑最有代表性的 3–5 行，**不要塞满**。
- 每行文字写完后心算一次宽度，超了就删字或换行，不许赌。

## 内容规则

- 图里的命令、文件名、IP、报错、配置项**必须取自文章正文**（文章已脱敏的照抄脱敏值），
  禁止编造文章里没有的事实。
- 标签/说明语言跟文章走（这个博客基本是中文）。
- 一张图只讲一个机制：封面讲「这篇是什么」，插图讲「某个流程怎么走」。
- 插图（放在正文里的那种）不要大页眉，让图本身占满画布，可留一行 16px 小标题。

## 渲染后自检（必做）

1. `Read` 生成的 PNG，逐项确认：文字没出卡片/画布边界、没有互相压盖、
   箭头确实连在两个元素之间、中文不是豆腐块。
2. 有问题改 SVG 重渲染，直到干净为止。
3. PNG ≤ 300KB（脚本已量化；超了说明元素太多，删）。
